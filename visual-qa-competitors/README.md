# Competitor/template screenshot library

Reference screenshots for the craft doctrine's lineup test and squint test (definitions live
in the doctrine itself, not restated here -- see `scripts/lineup-squint.js`'s own header
comment for the short version).

## Convention

One subdirectory per tool, named for the tool's own slug (the same slug its URL path uses):

```
visual-qa-competitors/<tool-slug>/*.png
```

Every image in a tool's subdirectory is a real screenshot of a real competitor or generic
template-look tool doing the same job, captured non-full-page at 1440x900 (the same
above-the-fold "hero view" the lineup test itself judges) -- use
`npm run capture-competitor-screenshot -- <url> visual-qa-competitors/<tool-slug>/<name>.png`
to add one. Aim for 4-5 per tool per the doctrine; more is a judgment call for whoever curates
the directory, fewer than 2 is refused by `scripts/lineup-squint.js` (there is no useful
"lineup" against zero or one comparator).

These files are committed, not regenerated by any build step -- a competitor site's own layout
changes on its own schedule, so refreshing an entry is a deliberate, human-triggered action,
not something CI re-fetches on every push. This is why this directory is NOT in `.gitignore`
the way `visual-qa-output/` (this repo's own regenerated screenshots) is.

## Producing a lineup + squint pair

```
npm run build
npm run lineup-squint -- dist/data/<tool-slug>/index.html visual-qa-competitors/<tool-slug>
```

Composes `<page>-lineup.png` (this repo's own screenshot alongside every competitor image in
one row) and `<page>-squint.png` (a heavily blurred variant of this repo's own screenshot) into
`visual-qa-output/` -- gitignored, regenerated per run, same as `visual-qa.js`'s own output.

## Recording a verdict

A reviewer views both composed images (with the `Read` tool, or by eye) and judges:

- **Lineup test:** is this repo's own tile identifiable at a glance as not-a-template, next to
  the real competitors?
- **Squint test:** does one dominant element's hierarchy survive the blur?

The verdict is recorded WITH the screenshots, not just asserted in prose elsewhere: copy that
run's two composed PNGs out of `visual-qa-output/` into the tool's own
`visual-qa-competitors/<tool-slug>/` directory as `verdict-<date>-lineup.png` /
`verdict-<date>-squint.png`, and commit a short `verdict-<date>.md` alongside them stating the
PASS/FAIL call and the one-line reasoning for each test. `visual-qa-competitors/hash-generator/`
has a real worked example.
